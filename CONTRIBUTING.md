# Регламент разработки (CONTRIBUTING.md)

### 1. Стратегия ветвления (Branching Strategy)
Это набор правил, определяющих, как создаются, именуются и сливаются ветки в репозитории. Наиболее распространённая модель — GitFlow:
* `main` — стабильная ветка, содержащая только релизный код.
* `develop` — ветка интеграции, куда сливаются готовые фичи.
* `feature/<номер_задачи>_<краткое_описание>` — ветки для разработки новых функций.
* `hotfix/*` и `release/*` — служебные ветки для исправлений и подготовки релиза.

### 2. Формат коммитов (Conventional Commits)
Стандарт оформления сообщений коммитов, принятый в ООО «Инфоком-С»:

`<тип>(<область>): <краткое описание>`

Примеры:
* `feat(api): add endpoint for projects list`
* `fix(db): correct migration for task table`
* `docs(readme): update deployment instructions`
* `chore(docker): add postgres container`

### 3. Процесс PR (Merge Request / Pull Request)
Это запрос на слияние ветки, который содержит:
* Описание изменений.
* Ссылку на задачу в трекере.
* Результаты автоматических проверок (CI).
* Обязательное одобрение ревьюера.
